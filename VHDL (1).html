Introducción

Esta investigación analiza siete códigos en VHDL (VHSIC Hardware Description Language), un lenguaje para describir circuitos digitales. Cada código se estudia línea por línea, con tablas e información complementaria. Los tres usan el estilo Behavioral (comportamiento): se describe qué hace el circuito, y la herramienta de síntesis decide cómo armarlo con compuertas y flip-flops.

Estructura común de un archivo VHDL

  • library / use: importan paquetes. STD_LOGIC_1164 define STD_LOGIC y STD_LOGIC_VECTOR. STD_LOGIC_ARITH y STD_LOGIC_UNSIGNED permiten operar vectores como números sin signo (por ejemplo, sumar con +).
  • entity: la "caja negra" con sus puertos de entrada (in) y salida (out).
  • architecture: lo que hay dentro de la caja. Entre is y begin se declaran señales; después de begin va la lógica.
  • process: bloque secuencial. Se ejecuta cuando cambia alguna señal de su lista de sensibilidad.
Dato: downto indica que el bit más significativo va a la izquierda. En (3 downto 0) el vector tiene 4 bits: bit 3, 2, 1 y 0.
Nota: STD_LOGIC_ARITH y STD_LOGIC_UNSIGNED no son estándar IEEE, son de Synopsys. Funcionan en ISE/Quartus y herramientas de la época, pero hoy se recomienda numeric_std.

1. Decodificador 2 a 4 (Deco24)

library IEEE;
use IEEE.STD_LOGIC_1164.ALL;
use IEEE.STD_LOGIC_ARITH.ALL;
use IEEE.STD_LOGIC_UNSIGNED.ALL;

entity Deco24 is
    Port (
        ctrl : in  STD_LOGIC_VECTOR(1 downto 0);
        dp1  : out STD_LOGIC_VECTOR(3 downto 0)
    );
end Deco24;

architecture Behavioral of Deco24 is

    signal ctrl1 : STD_LOGIC_VECTOR(1 downto 0) := "00";

begin

    ctrl1 <= ctrl;

    proc_deco: process(ctrl1)
    begin
        if (ctrl1 = "00") then
            dp1 <= "1110";
        elsif (ctrl1 = "01") then
            dp1 <= "1101";
        elsif (ctrl1 = "10") then
            dp1 <= "1011";
        else
            dp1 <= "0111";
        end if;
    end process proc_deco;

end Behavioral;

¿Qué hace?

Recibe un número de 2 bits (ctrl) y activa una sola de cuatro salidas (dp1). Es un circuito combinacional: la salida depende únicamente de la entrada actual, sin reloj ni memoria.

Explicación del código

  • Entidad: ctrl es la entrada de 2 bits (4 combinaciones) y dp1 la salida de 4 bits.
  • Señal ctrl1: copia interna de la entrada (ctrl1 <= ctrl). El := "00" es el valor inicial, útil en simulación.
  • Proceso proc_deco: sensible a ctrl1. Con if / elsif / else elige qué patrón de 4 bits se asigna a dp1.
  • El else final cubre el caso "11" y evita que se infieran latches (memorias no deseadas) porque todas las combinaciones quedan asignadas.

Tabla de verdad

ctrl(1..0)dp1(3..0)Salida en 0

101011dp1(2)
110111dp1(3)
Dato: las salidas son de lógica negativa (activas en bajo): la salida "seleccionada" es la que vale 0. Esto es típico para activar displays de ánodo común de 7 segmentos o para habilitar dígitos multiplexados (de ahí el nombre dp1) en tarjetas de desarrollo.

2. Contador de 2 bits (cont2)

library IEEE;
use IEEE.STD_LOGIC_1164.ALL;
use IEEE.STD_LOGIC_ARITH.ALL;
use IEEE.STD_LOGIC_UNSIGNED.ALL;

entity cont2 is
    Port (
        clk1 : in  STD_LOGIC;
        qs   : out STD_LOGIC_VECTOR(1 downto 0)
    );
end cont2;

architecture Behavioral of cont2 is

    signal cuenta : STD_LOGIC_VECTOR(1 downto 0) := "00";

begin

    proceso_cont: process(clk1)
    begin
        if rising_edge(clk1) then
            cuenta <= cuenta + 1;
        end if;
    end process proceso_cont;

    qs <= cuenta;

end Behavioral;

¿Qué hace?

Cuenta de forma ascendente 0, 1, 2, 3 y vuelve a 0, avanzando un paso en cada flanco de subida del reloj clk1. Es un circuito secuencial síncrono: tiene memoria (flip-flops).

Explicación del código

  • Entidad: una entrada de reloj y la salida qs de 2 bits con el valor de la cuenta.
  • Señal cuenta: guarda el estado actual. Se declara como señal porque un puerto out no se puede leer dentro de la arquitectura (en VHDL-93), y aquí necesitamos leer cuenta para sumarle 1.
  • Proceso: solo depende de clk1. rising_edge(clk1) detecta el paso de 0 a 1 del reloj.
  • cuenta + 1: posible gracias a STD_LOGIC_UNSIGNED. Con 2 bits, al llegar a "11" el siguiente valor es "00" (desbordamiento natural, módulo 4).
  • qs <= cuenta: asignación concurrente que conecta el estado interno a la salida.

Secuencia de conteo

Flanco012345
qs000110110001
Decimal012301
Nota: este contador no tiene reset. En hardware real arrancaría en un valor indefinido (el := "00" solo asegura el valor inicial en simulación y en algunas FPGA). Para un diseño robusto se agrega una entrada rst. Además, la salida qs también sirve como divisor de frecuencia: qs(0) vale la mitad de la frecuencia de clk1 y qs(1) la cuarta parte.

3. Registro de 4 bits (reg)

library IEEE;
use IEEE.STD_LOGIC_1164.ALL;
use IEEE.STD_LOGIC_ARITH.ALL;
use IEEE.STD_LOGIC_UNSIGNED.ALL;

entity reg is
    Port (
        D   : in  STD_LOGIC_VECTOR(3 downto 0);
        Q   : out STD_LOGIC_VECTOR(3 downto 0);
        clk : in  STD_LOGIC
    );
end reg;

architecture Behavioral of reg is

    signal dato : STD_LOGIC_VECTOR(3 downto 0) := "0000";

begin

    proceso_reg: process(clk)
    begin
        if rising_edge(clk) then
            dato <= D;
        end if;
    end process proceso_reg;

    Q <= dato;

end Behavioral;

¿Qué hace?

Es una memoria de 4 bits: cuatro flip-flops tipo D que comparten el mismo reloj. En cada flanco de subida de clk, la entrada D se copia a Q. Entre un flanco y otro, Q conserva su valor aunque D cambie.

Explicación del código

  • Entidad: D (dato de entrada), clk (reloj) y Q (dato almacenado).
  • Señal dato: el contenido guardado; inicia en "0000".
  • Proceso: en cada rising_edge(clk) se hace dato <= D. Fuera del flanco no se asigna nada, y por eso la herramienta infiere flip-flops (memoria).
  • Q <= dato: expone el valor almacenado en la salida.

Ejemplo de comportamiento

FlancoDQ después
110101010
200110011
311111111
Dato: los registros son la base de la memoria en sistemas digitales: guardan resultados, sincronizan señales y forman parte de contadores, máquinas de estados y procesadores.

4. Multiplexor 4 a 1 (mux41)

library IEEE;
use IEEE.STD_LOGIC_1164.ALL;

entity mux41 is
    Port (
        a, b, c, d : in  STD_LOGIC;
        sel        : in  STD_LOGIC_VECTOR(1 downto 0);
        y          : out STD_LOGIC
    );
end mux41;

architecture Behavioral of mux41 is
begin

    proc_mux: process(a, b, c, d, sel)
    begin
        case sel is
            when "00"   => y <= a;
            when "01"   => y <= b;
            when "10"   => y <= c;
            when others => y <= d;
        end case;
    end process proc_mux;

end Behavioral;

¿Qué hace?

Es un selector de datos: sel decide cuál de las cuatro entradas se copia a la salida y. Es lo contrario de un decodificador: allá un número elige una salida, aquí un número elige una entrada. También es combinacional.

Explicación del código

  • Lista de sensibilidad: incluye todas las entradas (a, b, c, d, sel), porque un cambio en cualquiera puede alterar la salida.
  • case: alternativa a if / elsif cuando se compara una misma señal contra varios valores. Todas las ramas son equivalentes entre sí, sin prioridad.
  • when others: obligatorio en VHDL, porque STD_LOGIC_VECTOR admite valores como 'U' o 'X' además de 0 y 1. Aquí cubre "11".

Dato: los multiplexores sirven para elegir entre fuentes de datos dentro de una CPU, para compartir una línea entre varios dispositivos y, junto con un contador, para recorrer varias señales por una sola salida.

5. Contador de 4 bits con reset y habilitación (cont4)

library IEEE;
use IEEE.STD_LOGIC_1164.ALL;
use IEEE.STD_LOGIC_ARITH.ALL;
use IEEE.STD_LOGIC_UNSIGNED.ALL;

entity cont4 is
    Port (
        clk : in  STD_LOGIC;
        rst : in  STD_LOGIC;
        en  : in  STD_LOGIC;
        q   : out STD_LOGIC_VECTOR(3 downto 0)
    );
end cont4;

architecture Behavioral of cont4 is

    signal cuenta : STD_LOGIC_VECTOR(3 downto 0) := "0000";

begin

    proceso_cont: process(clk, rst)
    begin
        if rst = '1' then
            cuenta <= "0000";
        elsif rising_edge(clk) then
            if en = '1' then
                cuenta <= cuenta + 1;
            end if;
        end if;
    end process proceso_cont;

    q <= cuenta;

end Behavioral;

¿Qué hace?

Es la versión completa del contador cont2: cuenta de 0 a 15, se detiene cuando en = '0' y vuelve a 0 con rst = '1'. Resuelve la falta de reset que se mencionó antes.

Explicación del código

  • Reset asíncrono: rst está en la lista de sensibilidad y se evalúa antes que el reloj, así que pone la cuenta en cero al instante, sin esperar un flanco.
  • Habilitación síncrona: en solo se revisa en el flanco de subida. Si vale 0, la cuenta se queda como está.
  • Orden de las condiciones: primero el reset, después el reloj. Ese orden hace que la herramienta infiera flip-flops con reset asíncrono.
Nota: también existe el reset síncrono, donde rst se revisa dentro de rising_edge(clk) y no aparece en la lista de sensibilidad. Es más seguro frente a ruido, pero necesita reloj para actuar. Con 4 bits el contador da 16 estados y su bit más significativo divide la frecuencia del reloj entre 16.

6. Registro de desplazamiento de 4 bits (regdesp)

library IEEE;
use IEEE.STD_LOGIC_1164.ALL;

entity regdesp is
    Port (
        clk : in  STD_LOGIC;
        rst : in  STD_LOGIC;
        sin : in  STD_LOGIC;
        q   : out STD_LOGIC_VECTOR(3 downto 0)
    );
end regdesp;

architecture Behavioral of regdesp is

    signal dato : STD_LOGIC_VECTOR(3 downto 0) := "0000";

begin

    proceso_desp: process(clk, rst)
    begin
        if rst = '1' then
            dato <= "0000";
        elsif rising_edge(clk) then
            dato <= dato(2 downto 0) & sin;
        end if;
    end process proceso_desp;

    q <= dato;

end Behavioral;

¿Qué hace?

Recibe un bit por la entrada serial sin y, en cada flanco de reloj, desplaza todo el contenido una posición a la izquierda. Convierte datos seriales en datos paralelos.

Explicación del código

  • dato(2 downto 0): toma los 3 bits bajos del registro (una rebanada o slice).
  • &: operador de concatenación. Pega esos 3 bits con sin a la derecha y arma de nuevo un vector de 4 bits. El bit 3 anterior se pierde.
  • Reset: limpia el registro a "0000".

Ejemplo: entrada serial 1, 0, 1, 1

Dato: los registros de desplazamiento se usan en comunicaciones seriales (UART, SPI), en contadores en anillo y en generadores de números pseudoaleatorios (LFSR). Desplazar un número a la izquierda equivale a multiplicarlo por 2.

7. Divisor de frecuencia (divfrec)

library IEEE;
use IEEE.STD_LOGIC_1164.ALL;
use IEEE.STD_LOGIC_ARITH.ALL;
use IEEE.STD_LOGIC_UNSIGNED.ALL;

entity divfrec is
    Port (
        clk_in  : in  STD_LOGIC;
        rst     : in  STD_LOGIC;
        clk_out : out STD_LOGIC
    );
end divfrec;

architecture Behavioral of divfrec is

    signal cont   : STD_LOGIC_VECTOR(24 downto 0) := (others => '0');
    signal estado : STD_LOGIC := '0';

begin

    proc_div: process(clk_in, rst)
    begin
        if rst = '1' then
            cont   <= (others => '0');
            estado <= '0';
        elsif rising_edge(clk_in) then
            if cont = 24999999 then
                cont   <= (others => '0');
                estado <= not estado;
            else
                cont <= cont + 1;
            end if;
        end if;
    end process proc_div;

    clk_out <= estado;

end Behavioral;

¿Qué hace?

Convierte un reloj rápido en uno lento. Con un reloj de entrada de 50 MHz (común en tarjetas FPGA), la salida cambia de nivel cada 25 000 000 de ciclos, así que produce una señal de 1 Hz, ideal para hacer parpadear un LED o avanzar un contador de forma visible.

Explicación del código

  • cont de 25 bits: 225 = 33 554 432, suficiente para contar hasta 24 999 999.
  • (others => '0'): forma abreviada de poner todos los bits en 0, sin importar el ancho del vector.
  • not estado: invierte la salida cada vez que el contador llega al límite. Cada inversión es medio periodo, por eso se cuentan 25 millones y no 50 millones.
Frecuencia de entradaCuenta máximaSalida
50 MHz24 999 9991 Hz
50 MHz249 999100 Hz
50 MHz24 9991 kHz
Nota: la fórmula es cuenta máxima = fentrada / (2 × fsalida) − 1. Usar la salida de un divisor como reloj de otros bloques es una práctica discutida: lo más recomendable es generar un pulso de habilitación (en) y mantener un solo reloj, como en cont4.

Posibles ampliaciones

  • Conectar la salida qs del contador a la entrada ctrl del decodificador: se obtiene un recorrido automático por 4 salidas, como un "barrido" de displays.
  • Combinar el contador con enable, el decodificador y el multiplexor en un sistema completo.
  • Hacer el contador descendente (cuenta - 1) o de módulo distinto de una potencia de 2.
  • Agregar una señal de habilitación en al registro.
